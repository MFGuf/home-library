# Картотека домашней библиотеки

Курсовой проект: настольное приложение для автоматизации учёта
и систематизации домашней библиотеки.

## Возможности

- **Хранение сведений о книгах**: название, авторы, издательство, год издания,
  ISBN, раздел библиотеки (беллетристика, специальная литература, хобби,
  домашнее хозяйство и др.), происхождение (покупка, подарок, по наследству),
  наличие в данный момент, статус чтения и субъективная оценка (1–10).
- **Учёт экземпляров книг**: у одной книги может быть несколько физических
  экземпляров с инвентарным номером, состоянием и годом поступления.
- **Поиск и фильтрация**: произвольный текстовый запрос (по названию, автору,
  издательству, ISBN) в сочетании с фильтрами по разделу, статусу чтения,
  наличию и минимальной оценке.
- **Инвентаризация**: сводка по состоянию библиотеки, список позиций
  с количеством экземпляров и экспорт картотеки в CSV-файл (UTF-8),
  открываемый в Excel.
- **Полный набор операций** над данными: добавление, просмотр,
  редактирование и удаление книг, авторов и разделов.

Все разделы расположены в одном главном окне (вкладки «Книги», «Авторы»,
«Разделы», «Инвентаризация»).

## Технологии и архитектура

| Слой        | Технология                          |
|-------------|-------------------------------------|
| Интерфейс   | JavaFX, FXML, CSS                   |
| Логика      | Java (принципы ООП, слои MVC)       |
| Хранение    | SQLite, JDBC (драйвер sqlite-jdbc)  |
| Сборка      | Maven                               |
| Тесты       | JUnit 5                             |

Проект разделён на классические слои:

```
ru.home.library
├── Main              — точка входа
├── model             — сущности (Book, Author, Category, BookCopy) и перечисления
├── database          — подключение к SQLite и инициализация схемы/демоданных
├── dao               — доступ к данным (паттерн DAO, интерфейс CrudDao)
├── service           — бизнес-логика (LibraryService)
└── ui                — контроллеры главного окна и форм, вспомогательные классы
```

Принципы ООП в проекте: **инкапсуляция** (закрытые поля моделей с доступом
через геттеры/сеттеры), **наследование** (базовый класс `Entity`),
**абстракция** (интерфейс `CrudDao` и `FormController`),
**полиморфизм** (единообразная работа DAO с разными сущностями).

## Требования

- **JDK 17 и новее** (проверено на JDK 21).
- Maven **не обязателен** — в проект встроен Maven Wrapper (`mvnw.cmd`).

## Запуск

### Командная строка (Windows, из корня проекта)

```bash
.\mvnw.cmd javafx:run
```

Если Maven установлен отдельно:

```bash
mvn javafx:run
```

### IntelliJ IDEA

1. `File → Open…` → выбрать папку проекта (файл `pom.xml`).
2. Дождаться импорта зависимостей Maven.
3. Открыть класс `ru.home.library.Launcher` и нажать **Shift+F10**
   (Run). Не забудьте выбрать SDK 17+.

> **Почему запускаем именно `Launcher`, а не `Main`?**
> `Main` наследует `javafx.application.Application` — такой класс нельзя
> запустить напрямую по обычному classpath, JVM выдаст ошибку
> `JavaFX runtime components are missing...`. Класс `Launcher` не наследует
> `Application` и просто вызывает `Main`, поэтому запуск из IDE работает.
> (Альтернатива — указать в настройках запуска `--module-path` и
> `--add-modules javafx.controls,javafx.fxml`, но `Launcher` проще.)

### Eclipse

1. `File → Import → Maven → Existing Maven Projects` → выбрать корень проекта.
2. Запустить класс `ru.home.library.Launcher`.

> Точки входа: `ru.home.library.Launcher` — для запуска в IDE
> и командой `mvn javafx:run`; класс `ru.home.library.Main` напрямую
> запускать не нужно (см. примечание выше).

## Тесты

```bash
.\mvnw.cmd test
```

Тесты используют базу данных в оперативной памяти и не затрагивают
файл БД приложения.

## Сборка jar

```bash
.\mvnw.cmd package
```

## База данных

Файл базы данных создаётся автоматически при первом запуске в каталоге:

```
<домашний каталог пользователя>\.home-library\library.db
```

Расположение можно изменить параметром запуска:

```bash
java -Dhome.library.db.dir=D:\путь\к\каталогу -jar ...
```

При первом запуске база наполняется демонстрационными данными
(несколько книг, авторов и разделов), чтобы приложение сразу было наглядным.
Удалите файл `library.db` — и при следующем запуске картотека создастся заново.

## Расширение проекта

Благодаря слоистой архитектуре новые возможности добавляются локально
в нужный слой:

- **новая сущность** — класс в `model`, DAO в `dao`, операции в `service`;
- **новое поле книги** — изменение модели, DAO и формы `book-form.fxml`;
- **отчёт** — метод в `LibraryService` (пример: экспорт в CSV);
- **поиск** — расширение `searchBooks(LibraryService)`.
